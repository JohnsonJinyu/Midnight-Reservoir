# Spectral Lake · 频谱湖面壁纸

可直接导入 **Wallpaper Engine**（Web 类型）的网页壁纸：紫橙发光的方块湖面（160×160 InstancedMesh + 自定义 GLSL），
上方是贴在同一块曲面幕布上的悬浮专辑卡与双行弧形歌词。

## 运行 / 导入

- 浏览器预览：直接打开 `index.html`（左下角面板可调参数，按 `H` 收起；加 `?clean=1` 隐藏面板）。
- Wallpaper Engine：**打开 → 动态壁纸 → 选择本目录的 `index.html`**（或把 `index.html` 拖到「创建壁纸」）。
  **不要选 `project.json`** —— 那会走场景编辑器入口：标题变成文件名、缩略图变成显示器图标、
  类型被判定成「本地场景」、面板顶部冒出「音频监听 / 主题配色 / 播放速度 / 翻转」这些场景专属项，
  真正的属性面板反而是空的。判断口径：**看到场景默认项 = 类型判错，先查 `project.json` 的 `file` 字段。**
  属性面板里会出现 `project.json` 定义的 36 项，按 5 组折叠：**音频律动 / 镜头与地形 /
  性能与画质 / 音乐信息卡 / 歌词**（配色常驻在最上面，不折进分组）。
  浏览器里想快速比对清晰度档位，加 `?res=hd|qhd|uhd`。
- 改动 `project.json` / `index.html` / 增删文件之后，先跑一遍自检：
  `node tools/validate-project.js`（漏字段、资源缺失、加载顺序反了都会直接报出来），
  动了属性面板再加一遍 `node tools/audit-props.js`。

## 文件结构（一层一个文件，改一层不会碰到另一层）

```
index.html          加载顺序与演示面板 DOM
project.json        WE 属性定义（41 条目 = 36 属性 + 5 个分组，order 0–40 唯一）
preview.jpg         工坊预览图（1920×1080）
three.min.js        three.js r147（本地，无 CDN）

js/core.js          CFG 默认值 / 共享状态 S/MEDIA/LYRICS / 常量 / clamp —— 唯一的参数表
js/audio.js         音频输入与分析：WE 回调、演示信号、包络、节拍波源
js/band.js          幕布曲面：唯一的曲率定义，所有内容都贴在它上面
js/media.js         系统媒体会话判断 + 专辑卡（封面/歌名/进度线）+ 待机光点
js/lyrics.js        歌词：LRC 加载解析缓存、双行排版、换句动画、贴到幕布
js/shaders.js       两个 GLSL 源码字符串（纯数据，不含逻辑）
js/lake.js          渲染器/画布尺寸（分辨率档位）、主题、大气、相机、材质、出图
js/props.js         WE 用户属性 + 浏览器面板接线（唯一的参数写入口）
app.js              启动与主循环：帧调度 + 按顺序调各层
tools/validate-project.js  project.json / 入口 / 资源的自检脚本
tools/audit-props.js      属性 ↔ 代码一致性审计（控件是否有代码接、取值是否合法、档位是否够细）
tools/probe-props.js      属性换算单测（遍历滑块每一个落点）
tools/sync-lyrics.js       从播放器缓存同步歌词（增量 / --watch）
tools/qq-qrc.js            QQ 音乐 QRC 解码器（QMC1 异或 + 专用 3DES + zlib）
同步歌词.bat               双击跑一次同步
歌词同步-常驻.bat          双击进入边听边补模式
```

依赖顺序 = 上面自上而下的顺序，`index.html` 里就是按这个顺序 `<script>` 的。
没有构建步骤、没有模块打包（WE 用 `file://` 加载，ES Module 会被 CORS 拦），
所以模块之间靠**全局函数 + 明确的契约**通信，而不是 import。

### 五条必须守住的契约

1. **曲率只有一个来源**（`js/band.js`）
   `bandPatchGeometry(cx, w, h, rOff, seg, refWidth)`。任何新内容要贴到幕布上，都调这个函数，
   不要自己写 z 公式、也不要在画布上画假弧度。同一组内容必须传同一个 `refWidth`，
   否则封面和歌名会弯成两种弧度。

2. **字号用世界单位，不用画布像素**（`js/lyrics.js` 的 `LYRIC_TYPE` + `LYRICS_PPU`）
   历史坑：早期字号写的是「84px @ 1024 宽画布」，后来画布改成 2048、幕布加宽，
   字号没跟着改，屏幕上的字就悄悄变小、弧度也跟着消失 —— 表现为「改着改着视觉效果没了」。
   现在 `LYRIC_TYPE.active = 1.60` 是**世界单位**，画布像素只是换算结果，分辨率无关。
   另外：单行宽度还有一个显式上限 `LYRIC_MAX_W = 27`（世界单位）。长歌词靠
   `shrink` 自动缩字才放得下 —— 这个上限以前是「画布宽度」隐含给的（2048 ÷ 72 = 28.4 单位），
   结果长句会铺掉半个屏幕、而且 `歌词大小` 滑块对它几乎无效（缩字已经顶到上限）。

   **上限怎么选**（三个约束卡出来的区间）：

   | 约束 | 换算 | 允许的上限 |
   |---|---|---|
   | 画布可用宽 2028px ÷ PPU 72 | 28.17 | ≤ 28 |
   | 幕布留白 ×1.07 不超过画布 2048px | 2048÷72÷1.07 | ≤ 26.6（超出只是留白被压，不影响字号） |
   | `歌词大小` 拖到 1.3 时不缩字 | 27 → 13 字 | 越大越宽松 |

   取 **27**。实测「开始缩字」的门槛（中文全角字宽 ≈ 1em，按 `lyricMeasure` 的实际量宽）：

   | 字号 | 上限 22 时 | 上限 27 时 |
   |---|---|---|
   | 0.6 | 23 字 | 29 字 |
   | 0.9 | 16 字 | 19 字 |
   | 1.1 | 13 字 | 16 字 |
   | 1.3 | **11 字** | **13 字** |

   中文歌词一行多在 13 字以内，所以拖到最大时长句也能跟着变大，不再被压回去。
   16:9 下最长行约占屏宽 44%，4:3 下约 58%，两种比例都不会溢出画面。
   想再放宽必须同时提 `LYRICS_BASE_W`，否则会踩到画布宽这条隐藏约束。

3. **幕布宽度由文字宽度反推**
   歌词幕布宽 = 最长那一行 × 1.07。文字永远占满幕布，曲率就一定作用在文字上；
   如果幕布固定很宽、文字只占中间一小段，两端进深只有零点几，屏幕上就是一条直线（这就是「塌成平幕」）。

4. **像素密度只由两处决定**（`js/lake.js` 的 `renderPixelRatio()` + `js/lyrics.js` 的 `syncLyricsResolution()`）
   渲染分辨率档位管住 WebGL 后备缓冲的高度（1080/1440/2160，最多 2× 超采样），
   歌词画布再按同一个倍率重建 —— 字的**世界尺寸**不变，只是每单位塞进更多像素。
   所以「换档位只改清晰度，不改构图」；任何新增的 canvas 贴图都要照这个规矩挂上去。

5. **`project.json` 顶层必须同时有 `type` 和 `file`**
   ```json
   { "type": "web", "file": "index.html", "title": "...", "preview": "preview.jpg" }
   ```
   少了 `file`，WE 找不到 web 入口，会**静默退回按 Scene 解析**：标题变成 `project.json`、
   缩略图变成显示器图标、类型显示「本地场景」、右侧面板冒出一堆场景默认项
   （音频监听 / 播放速度 / 翻转 / 图片筛选器 / 显示颜色选项），还会往工程里编译 `shaders/*.dxs`。
   表现看着像「歌词没了、属性没了」，实际跟渲染代码无关。跑 `node tools/validate-project.js` 可提前拦住。

## 属性面板：分组与控件选择

### 分组机制（`type: "group"`）

`group` 是官方支持的特殊属性类型：**它之后的所有属性都归它管**，直到出现下一个 `group`。
所以「分组结束」不是靠闭合标签，而是靠**再写一个 group**；第一个 group 之前的属性不归属任何分组
（当前就是置顶常驻的「配色」）。`group` 只需要 `order` 和 `text`，不要写 `value`。

### 三类控件怎么选

| 控件 | 什么时候用 | 关键字段 |
|---|---|---|
| `combo` 下拉 | 档位有限、需要**可复现的精确值**（分辨率、清晰度、FPS 上限、配色） | `options[{label,value}]`，`value` 必须是字符串 |
| `slider` 滑块 | 需要连续调手感；步进由 `fraction` + `precision` 决定 | 见下方「滑块步进的坑」 |
| `textinput` 文本框 | **需要敲具体数字**、滑块给不准的项（歌词时间偏移 ms、磁盘路径） | `value` 用字符串；解析与兜底在 `props.js` 里做 |
| `bool` 复选框 | 纯开关 | `value` 必须是 `true` / `false`，不加引号 |

判据一句话：**能用「档」表达的就别给滑块，能量化到整数的就别给小数，能敲数字的就别让人拖。**

### 滑块步进的坑（一定要看）

官方文档原文：开了 `fraction` 才会出现 `precision`，**`precision` 默认 2，代表 0.1 的步进**。
也就是说步进 = `10^(2 - precision)`：

| `precision` | 实际步进 |
|---|---|
| 2（默认） | 0.1 |
| 1 | **1.0** ← 陷阱 |
| 0 | 10 |

所以「歌词大小 0.6–1.3 配 `precision: 1`」等于只剩 0.6 和 1.6 两档，滑块看着像坏了。
**WE 能做到的最细步进就是 0.1**，想要更细只能把数值域放大。

现在的做法：所有需要细调的滑块都改用**整数域**，最细再换算回实数。
`props.js` 用 `propScaled(v, scale, min, max, def)` 统一做除法，`project.json` 里看不到小数：

| 类型 | 域 | 换算 | 等效步进 | 例子 |
|---|---|---|---|---|
| 百分比型（强度/缩放/速度） | 40–300 之类 | `/100` | 0.01 | 歌词大小 60–130 → 0.60–1.30 |
| 位置型（高度） | -80–80 | `/10` | 0.1 | 专辑高度 12 → 1.2 |

属性 `text` 里带上 `（%）` 或 `（×0.1，10 = 1.0）`，用户看到 90 就知道是 90%。
`tools/probe-props.js` 会遍历每一个整数落点，确认没有跳档、没有重复。

### 当前的 5 组划分

| 分组 | 内容 | 调节方式 |
|---|---|---|
| （置顶，不分组） | 配色 | 下拉 |
| 音频律动 | 灵敏度 / 起跳 / 回落 / 低频展开 / 频率定位 / 波纹 / 顶面发光 / 静音呼吸 | 整数百分比（40–300 等） |
| 镜头与地形 | 仰角 / 水平角度 / 镜头距离 / 视野 / 地形范围 / 鼠标视差 | 整数（地形范围用整数百分比） |
| 性能与画质 | 渲染分辨率 / 渲染清晰度 / FPS 上限 | 全部下拉档位 |
| 音乐信息卡 | 只听音乐 / 显示卡片 / 卡大小 / 环绕 / 高度 / 歌名大小 / 待机光点 | 整数百分比、整数、×0.1 |
| 歌词 | 显示 / 大小 / 弧度 / 高度 / 环绕 / **时间偏移（文本框）** / 署名 / 联网 / 路径 / 诊断 | 整数百分比、×0.1、文本框 |

`props.js` 里所有数值入口都过 `propNum()`：combo 传的是字符串、文本框可能是 `-350`、
`−800`（全角负号）、`350ms`、全角数字 `１２０` 甚至空串，解析不出数字就退回默认值 ——
绝不让 `NaN` 流进 `CFG`，因为 `NaN` 在这些参数里是静默失效（不报错、动画直接不动）。
时间偏移额外做严格校验：认不出格式就归零，不做「猜数字」。

改过 `project.json` 之后跑三个自检，分工不同：

| 脚本 | 管什么 | 典型能拦住的问题 |
|---|---|---|
| `node tools/validate-project.js` | WE 能不能正确解析这份 `project.json` | 缺 `file` 被当成 Scene、`order` 重号断号、分组为空、资源缺失、脚本加载顺序反了 |
| `node tools/audit-props.js` | 面板上的控件是否真的接上了代码 | 属性定义了但 `props.js` 从不读（拖了没反应）、`CFG` 被赋值却没渲染代码消费、combo 默认值不在 options 里、condition 引用了不存在或非 bool 的属性、仍开着 `fraction` 的滑块 |
| `node tools/probe-props.js` | 「面板读数 → CFG 实数值」的换算有没有被改坏 | 整数档位跳档/重复、越界没夹住、脏输入漏进 `NaN`、旧属性 key 又被误读 |

### 标题长度

右侧面板宽度有限，`text` 超过约 20 个汉字宽就会折行、把控件挤下去。当前最长的一项是
「歌词弧度（%，0 = 平幕）」23 宽，其余都在 22 以内。写新属性时把解释放在括号里、一句话说完，
不要写成「（可选：放 .lrc 的目录，多个用分号分隔）」这种 50 宽的长句。

## 幕布曲面（物理含义）

```
z(x) = -(R - rOff) + x² / (2·Rc)      R = 40（距离），Rc 由「歌词弧度」滑块控制
```

中央最远、两侧朝观众卷过来 —— 相当于站在环形幕布内部靠前的位置。透视投影自动得到
「中间的字小、两端的字大」以及两头被拉高的弧线，不是画布上画出来的假弧。
`Rc` 按内容宽度归一（`Rc = refWidth / (8 × 0.12 × curve)`），所以短句不会因为只占幕布中间而变平。

## 渲染分辨率档位

WE 没有现成的「分辨率」属性：网页壁纸的画布永远等于窗口大小。所以我们自己控制后备缓冲：

| 档位 | 效果 | 适用 |
|---|---|---|
| 跟随窗口（auto） | 1 CSS 像素 = 1 渲染像素 | 老行为，最省 |
| 1080p | 后备高度钉到 1080 | 4K 屏上 `dpr` 只有 0.5，弱显卡救命 |
| 2K / 1440p | 高度钉到 1440 | 1440p 屏或 2K 超采样 |
| 4K / 2160p | 高度钉到 2160（上限 2× 窗口） | 1080p 屏做超采样 / 4K 屏原生 |

「渲染清晰度」滑块是在档位之上再乘 0.75–2 的微调量。两者相乘后夹在 0.5–2.0，
保证任何组合都不会把显存打爆（25600 根方块 + 长片元着色器，像素量是线性成本）。

## 歌词来源优先级

```
手动路径 lyricsfile
  → lyrics/_index.json 三重比对命中（同步器生成，见下）
  → lyrics/ 里的同名文件
  → 用户歌词文件夹 lyricsdir（分号分隔多目录）
  → localStorage 历史缓存
  → 在线（music-api.gdstudio.xyz，只有 netease / joox 两个源可用）
```

### 为什么优先用本地缓存（QQ 音乐）

同名不同曲是这里最容易翻车的点。实测搜索「`你像风一样出现 玉芬`」，接口返回的
全是「**玉芬阿 / DJ阿谭**」的另一个版本，原唱根本不在结果里 —— 按歌名匹配就会
显示成另一首歌的词。本地缓存不存在这个问题：它就是播放器此刻显示的那份。

壁纸本身是网页，**没法列目录、也读不到工程外的文件**（WE 的 file 处理器只放行工程目录），
所以由工程外的 Node 脚本解密再落进来：

```
node tools\sync-lyrics.js           一次性同步（或双击 同步歌词.bat）
node tools\sync-lyrics.js --watch   常驻，每 20s 增量同步（双击 歌词同步-常驻.bat）
node tools\sync-lyrics.js --dir <路径>  缓存不在默认位置时手动指定
```

`tools/qq-qrc.js` 是纯 Node 的 QRC 解码器（无第三方依赖），链路实测为：

```
QMC1 异或（PRIVKEY 128 字节循环）→ 去掉 11 字节头 → QQ 专用 3DES → zlib 解压 → QrcInfos XML
```

其中 3DES 是 QQ 自己改过的 DES（S 盒笔误、15 轮加半轮、末轮不交换左右半边），
**标准库的 3DES 解不开**，所以实现了内置版本。解出来的逐字时间轴会被压成标准 LRC。

同步器产出：

| 文件 | 作用 |
|---|---|
| `lyrics/<歌名> - <歌手>.lrc` | 标准 LRC（逐行时间轴，去掉逐字标记） |
| `lyrics/_index.json` | 每条含歌名 / 歌手 / 时长，供壁纸按「歌名+歌手+时长」三重比对挑选 |
| `lyrics/.sync-state.json` | 增量用的 mtime+size 记录，避免每次重解全部文件 |

纯音乐条目（`此歌曲为没有填词的纯音乐`）不入 .lrc，只在索引里打 `j:1`，
壁纸看到就显示「纯音乐」，不再去网上抓一首同名的错歌。

### 在线兜底的硬门槛

歌名必须对得上，**且**歌手和时长至少有一项能对上，否则整条丢弃（宁可没词也不串词）：
歌手按分隔符拆成名字逐个比对，要求「整名相等」或「两边都 ≥4 字且互相包含」——
`玉芬阿` 不再被当成 `玉芬`；`群星` 这类合辑写法例外，只认歌名完全一致。

## 已知限制

- WE 只转发**当前那一个**系统媒体会话。若它转发的恰是暂停的腾讯视频，JS 拿不到 QQ 音乐的歌名，
  这时只能选择「什么都不显示」（`只显示播放中的音乐` 开关就是干这个的），没有别的办法。
- WE 的 `file` / `directory` 属性只支持图片视频，本地 `.lrc` 只能走 `textinput` + XHR；
  `file://` 下读本地文件可能被浏览器拦（此时会自动回落到在线歌词）。
